# Мониторинг

Начиная с 0.5.7, «Наблюдение → Состояние системы» показывает состояние текущего тенанта. Обновление ручное. `/api/health` возвращает те же данные в JSON, `/metrics` — Prometheus text format 0.0.4. Оба маршрута используют существующий административный вход и требования TLS/mTLS. Для тенанта пути имеют префикс `/t/<id>`. Не публикуйте их без аутентификации.

Для Prometheus используйте HTTPS, корректную проверку CA и `basic_auth` административной учётной записи соответствующего тенанта; при обязательном mTLS нужен клиентский сертификат. Пароль храните через `password_file`, не в репозитории. Отдельной роли только для чтения метрик пока нет.

Счётчики хранятся в памяти отдельно для каждого Store/тенанта и сбрасываются при его открытии или перезапуске. Они не восстанавливаются из журнала. Метки ограничены фиксированными именами операций и результатов: пользователей, IP, текстов ошибок и секретов в экспорте нет.

- `border_operations_total`, `border_results_total`, `border_failures_total`: число операций, результатов и ошибок. RADIUS Reject — штатный результат, отдельно от ошибок обработки; неверный пароль в identity_auth учитывается как ошибка проверки, а не доказательство недоступности LDAP.
- `border_operation_duration_seconds_sum/count/max`: суммарная длительность, количество и максимум с запуска; это не перцентили и не скользящее окно.
- `border_last_operation_seconds`, `border_runtime_started_seconds`: время последней операции и запуска счётчиков. Ноль означает отсутствие наблюдений.
- `border_database_up`, `border_database_query_seconds`: результат и длительность фактического запроса к БД с таймаутом 3 секунды.
- `border_active_sessions`, `border_stale_sessions`, `border_pending_revocations`: полные количества в БД, независимо от лимита списка сессий. При ошибке БД эти показатели не экспортируются; `/api/health` возвращает 503, `/metrics` — 200 с database_up=0.

RADIUS учитывается после выбора тенанта, включая отбрасывание запроса неизвестного NAS. Успешный ответ означает обработку, а не подтверждение доставки клиенту. Ошибки выбора тенанта и отброшенные из-за очереди/размера UDP-пакеты относятся к корневой среде; успешные маршрутизации не считаются. Повторные accounting-пакеты учитываются как операции, даже если запись в БД дедуплицирована.

Фоновые account_sync, revocation и retention отражают проходы задач, включая проходы без работы и отключённую очистку. Ошибки отдельных проверок пользователей и CoA/Disconnect видны в identity_status и session_action: успешный проход не означает доступность всех внешних систем. SMTP/SMS/push отражают вызовы сервиса уведомлений; push с нулём отправок отмечается empty. Это наблюдения фактических операций, а не активные сетевые пробы.

Спецификация экспорта: https://prometheus.io/docs/instrumenting/exposition_formats/
