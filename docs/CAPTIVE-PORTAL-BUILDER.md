# Конструктор captive portal

Раздел «Конфигурация → Интеграции → Captive portal» задаёт оформление отдельно
для текущего тенанта, его доменов и NAS. Приоритет: собственный макет NAS,
затем домена из подписанного перехода, затем тенанта, затем встроенный макет.
Переключатель «Собственное оформление» выключает наследование для выбранной
области целиком. Выключение сохраняет макет для последующего включения.

Можно загрузить фон PNG/JPEG (до 2 МиБ, до 4096 пикселей по стороне и 12 Мп),
изменить заголовок, описание и подписи обеих кнопок. Карточка перемещается
перетаскиванием в одну из девяти адаптивных позиций; тот же выбор доступен
с клавиатуры. Кнопки располагаются над/под полями и выравниваются отдельно.
Есть мобильный предпросмотр. Произвольный HTML/CSS/JS и внешние URL не принимаются.

Фон сохраняется отдельной операцией сразу; остальные изменения — по кнопке
сохранения. Изображение хранится в settings текущей базы тенанта, поэтому входит
в резервную копию базы и не требует внешнего хранилища. Бинарник остаётся один.

API администратора (обычная авторизация и CSRF):

- GET/POST `/api/portal-design?scope=tenant`
- GET/POST `/api/portal-design?scope=domain:corp`
- GET/POST `/api/portal-design?scope=nas:192.0.2.1`
- POST `/api/portal-design/background?scope=...` — байты изображения;
  пустое тело удаляет фон. POST настроек не заменяет фон через поле Background.

Домены и NAS должны существовать в текущем тенанте. Гостевой
POST `/api/guest/design` принимает Token, проверяет подпись NAS и срок перехода
и возвращает эффективное оформление. Обычный query-параметр domain не выбирает
оформление. Доверенный генератор `/api/guest/link` принимает необязательное поле
Domain, включаемое в подпись. Старые переходы без домена используют NAS/тенант.
У адаптера NAS следует передавать тот же домен; в существующем контракте Redirect
это необязательное поле `d`.

Это конструктор гостевого портала. Политика выдачи доступа настраивается отдельно; оформление не даёт доступа
и не заменяет NAS/UAM-адаптер. Редирект Netcraze/Chilli и реальное открытие сети
не считаются проверенными без испытания на устройстве.

## Два шага и выбор канала

LoginMethod: `sms` (по умолчанию), `email`, `both`. Выбор наследуется вместе
с макетом NAS/домена/тенанта и проверяется сервером. Экран 1 показывает кнопки доступных способов входа. После выбора SMS/email
экран 2 запрашивает контакт, экран 3 — код. Есть возврат для изменения контакта. Предпросмотр
конструктора переключается между экранами; оба поля одновременно не показываются.

POST `/api/guest/start` принимает Token, Channel и Phone либо Email.
Старый запрос с Phone без Channel сохраняет смысл SMS. Ответ содержит Channel
и MaskedContact; MaskedPhone сохранён для совместимости. SMTP выбирается по
домену подписанного перехода, иначе по домену одиночной политики NAS, иначе
по настройкам тенанта. Email получателя не определяет домен настроек.
SMS также учитывает подписанный домен. Недоступный канал не заменяется другим.

Почтовый и SMS-код действуют 5 минут, допускают не более 5 попыток и однократное
использование. Общий лимит устройства распространяется на оба канала; смена
канала не обходит интервал повторной отправки 60 секунд. Контакт хранится
зашифрованным, в журнале и списке сессий используется маска. Старые имена колонок
phone_cipher/phone_hash/masked_phone теперь используются и для email-контактов.
Настройка политики может быть включена до настройки отправителя; при выдаче
кода доступность выбранного scoped-канала проверяется, ошибка доставки
аннулирует код. Реальная SMTP-доставка требует настроенного канала уведомлений.

## Места для SSO

SSOEnabled включает необязательный блок, SSOPosition задаёт `top`/`bottom`
относительно формы контакта. SSOProviders содержит выбранные идентификаторы:
`yandex`, `gosuslugi`, `google`, `apple`, `vk`, `oidc`.
SSO отображается только как заготовка в предпросмотре экрана выбора. В публичном
портале неподключённые SSO-провайдеры скрыты, даже если отмечены в конструкторе. OAuth/OIDC/ЕСИА, callback, client secret, согласия и
привязка полученной личности к разрешению доступа пока не реализованы.


## Доступные способы входа

Ответ `/api/guest/design` дополнен `Methods`: пересечение LoginMethod макета
и настроенных каналов уведомлений в доверенной области NAS/домена/тенанта.
Отключённая гостевая политика возвращает пустой список. Проверка конфигурации
не отправляет пробное сообщение и не гарантирует текущую сетевую доступность
SMTP/SMS. Ошибка реальной доставки показывается после запроса кода.
При пустом списке посетитель видит сообщение об отсутствии способов входа.
Даже единственный доступный метод показывается кнопкой на первом экране.
Предусмотрен возврат к выбору метода и к вводу контакта.
