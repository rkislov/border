# Публичный гостевой портал через FESS

Проверено 23.11.2026: Netcraze Ultra NC-1812, NDMS 5.1.8, macOS 27.2.1,
Border 0.5.9-netcraze. Использован отдельный тенант `netcraze-lab`, заранее
изолированный сегмент и временный SSID `Border-Lab-Portal`.

## Публикация

В действующей установке `BORDER_PORTAL_URL=https://border.kislovs.ru`.
FESS завершает публичный TLS и передаёт запросы через защищённый SSH-туннель
на основной HTTPS-listener Border, `127.0.0.1:18443`.

- Корневой портал: `https://border.kislovs.ru/portal/default/`.
- Портал тенанта: `https://border.kislovs.ru/portal/<tenant>/`.
- Старт гостевого входа задаётся подписанным переходом NAS. Самостоятельное
  открытие `/guest` без такого перехода не даёт разрешения на доступ.
- UAM URL копируется из настроек адаптера NAS. Для испытанного тенанта:
  `https://border.kislovs.ru/portal/netcraze-lab/uam/netcraze/<NAS-IP>`.

FESS должен сохранять исходные путь и query string: подпись UAM проверяет
точный публичный URL. Нельзя перенаправлять подписанный переход на другое
имя хоста или менять его параметры. Портал тенанта использует свои политики,
каналы уведомлений и ключи; настройки корневого портала их не заменяют.

## Доступ до авторизации

На Chilli разрешаются DNS и HTTPS портала до входа. В проверенной схеме
использованы точный домен `border.kislovs.ru` в `chilli uamdomain` и TCP/443
публичного IP FESS в `chilli uamallowed`. IP нужно получать из актуального DNS,
а не копировать адрес origin-сервера. Изменение адреса публикации требует
обновления разрешений NAS. Общий IP reverse proxy разрешает доступ и к другим
сервисам этого IP в пределах сетевого правила; учитывайте это при выборе
отдельного адреса для гостевого портала.

Не добавляйте адреса проверки подключения ОС, например `captive.apple.com`,
в список доступа до входа: клиент должен увидеть перенаправление на портал.
Публичный сертификат проверяется штатно; установка тестового CA для этой
страницы не требуется. Разрешения OIDC-провайдеров добавляются отдельно,
когда соответствующий способ входа действительно включён.

## Результаты

До входа внешний HTTPS блокируется, HTTP возвращает подписанный UAM-переход.
Портал доступен через FESS с обычной проверкой сертификата. Проверена
последовательность выбора email, ввода адреса и отдельного экрана кода.
Неверный код отклонён. После правильного кода интерфейс показывает
«Доступ открыт», RADIUS Accounting подтверждает сессию, HTTPS работает
без переподключения Wi-Fi. Домашнее управление из гостевой сети недоступно.

Проверены HTTP-клиент, браузер и полный вход через системный Captive Network
Assistant macOS. Для последнего сеть выбиралась в штатных настройках Wi-Fi;
окно открылось автоматически, показало форму и приняло код. При предыдущих
программных подключениях наблюдались закрытие окна и возврат в домашнюю сеть.
В повторном прогоне через настройки это не воспроизвелось; точная причина
предыдущего поведения не установлена, оно не считается исправлением Border.

После досрочного отзыва HTTPS заблокирован, HTTP снова направляет на портал.
В измеренном публичном прогоне блокировка заняла 13,2 секунды при оставшейся
581 секунде разрешения. Нативная сессия macOS также отдельно отозвана.
При разрешённом доступе проверка Apple возвращала HTTP 200, после отзыва — 302.

Письма отправлялись штатным SMTP-клиентом Border в изолированный TLS-приёмник.
Внешние SMTP и SMS по решению владельца подключаются позже; реальная доставка
и вход через внешнего IdP не заявляются проверенными. Секреты, коды и захваты
трафика сохранены вне репозитория. По завершении тестовые каналы и гостевой
доступ отключены, временные туннели и правила удалены, домашняя сеть восстановлена.

Источники для настройки: [Captive Portal Netcraze](https://support.netcraze.ru/ultra/nc-1812/ru/15226-captive-portal.html),
[CLI Ultra 5.1](https://files.support.netcraze.ru/Download/CLI/5.1/RU/cli_manual_nc-1812.pdf),
[описание обнаружения captive-сетей Apple](https://developer.apple.com/news/?id=q78sq5rv).
DHCP option 114 / CAPPORT API в этот прогон не входили.
