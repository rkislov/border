# Встроенный гостевой адаптер Netcraze / Keenetic

Адаптер Chilli входит в `radiusd`: отдельный процесс управления не требуется.
Он подключён к общей очереди SMS/email/OIDC в корневой базе и каждой базе
тенанта. Требуется компонент Captive Portal на NAS и заранее созданная
изолированная гостевая сеть. Сам адаптер не меняет SSID, мосты и правила сети.

## Настройка в панели

В разделе «Инфраструктура → Сетевые устройства · NAS» выберите профиль
«Netcraze / Keenetic», сетевой режим и разрешите гостевой портал. Зарегистрируйте
NAS под фактическим IP источника RADIUS и ответов Disconnect. При подключении
через VPN это может быть адрес туннеля, а не домашний LAN-адрес.

Откройте «Гостевой адаптер» у нужного NAS и заполните:

- Адрес управления `https://IP:порт`, служебную учётную запись и SHA-256
  отпечаток сертификата, полученный по доверенному каналу. Используется
  точный отпечаток DER-сертификата, не отпечаток публичного ключа.
- Если веб-интерфейс требует другого Host/SNI, укажите его отдельно.
  DNS-имя в адресе подключения не используется; запрос идёт на заданный IPv4.
- Если HTTPS на NAS недоступен, допускается HTTP к частному адресу только
  внутри отдельно защищённого туннеля и с явным включением этой опции.
  Частный адрес сам по себе не обеспечивает шифрование.
- Интерфейс `ChilliN`, обслуживающий его `BridgeN`, IPv4-подсеть, логический
  сегмент Border и VLAN его сопоставления для этого NAS/расположения.
- Домен портала либо портал тенанта; NAS-Identifier; IP и порты RADIUS.
- Отдельный секрет UAM не короче 16 символов. Скопируйте показанный адрес
  перехода в `uamserver` на NAS. Для тенанта он содержит `/portal/<tenant>/`.

Сегмент должен быть разрешён гостевой политикой. Сопоставление VLAN описывает
уже настроенную сеть: Chilli не переносит клиента в другой VLAN этой командой.
Настройте на NAS тот же UAM-секрет, RADIUS-секрет, NAS-IP, NAS-Identifier,
Authentication/Accounting и CoA-порт. Разрешите доступ к порталу и необходимым
OIDC-провайдерам до авторизации. Клиентам нужен доверенный HTTPS портала.

Включите и сохраните адаптер. Кнопка «Проверить сохранённые настройки» входит
в RCI и читает параметры Chilli; не выполняет login/logout и не меняет сеть.
Она проверяет включённый защищённый мост, подсеть, UAM, секреты и RADIUS.
Успешная проверка конфигурации не заменяет сквозной гостевой вход и Accounting.

Пароль и UAM-секрет хранятся зашифрованными ключом соответствующего тенанта,
с дополнительной привязкой к NAS. API никогда не возвращает их в панель.
Пустые поля сохраняют секреты. При смене адреса управления, Host, пользователя,
сертификата или режима HTTP пароль нужно ввести повторно. Изменение настроек
отзывает прежние гостевые разрешения этого NAS; сохранение без изменений — нет.
Настройки доступны только администратору, запись защищена CSRF.

## Проверки при открытии доступа

1. Переход `/uam/netcraze/<nas>` проверяет подпись точного UAM URL, NAS-Identifier,
   MAC, Session-ID, challenge, подсеть и параметры NAS. Из браузера не принимаются
   адрес управления, домен политики, команды или URL последующего перехода.
   Запрос с неверной подписью не вызывает подключение к NAS.
2. Подтверждённый SMS/email/OIDC-вход сохраняет исходный Session-ID вместе
   с разрешением. Перед командой снова проверяются срок, политика, сегмент,
   домен, поколение разрешения и актуальность настроек адаптера.
3. RCI читает список Chilli. Чужая, изменившаяся или неоднозначная сессия
   блокирует команду. Незавершённая сессия может отсутствовать в списке:
   защитой при активации служит обязательное совпадение `Acct-Session-Id`
   в RADIUS Access-Request с Session-ID подписанного перехода. Без этого
   атрибута Border отказывает с причиной `guest NAS session mismatch`.
4. Команда `chilli login` использует только нормализованный MAC и проверенное
   имя интерфейса. Повтор при уже авторизованном том же клиенте не выполняет
   новый login. Перезапуск Border сохраняет очередь и её ограничения.
5. Ответ команды означает ожидание Accounting. Только сессия с Class текущего
   разрешения подтверждает открытие доступа. Исчерпание повторов, отзыв и
   ошибки показываются через существующую диагностику гостевого входа.

Транспорт ограничивает время и размер ответов, не использует системный proxy
и не следует HTTP-перенаправлениям. HTTPS проверяет закреплённый сертификат
и срок его действия. Сырые ответы NAS и учётные данные не попадают в ошибки API.

Отзыв выполняется общим механизмом RADIUS Disconnect с проверкой ответа и
поколения сессии. Резервный logout по одному MAC намеренно не используется:
он мог бы отключить новое соединение после быстрого переподключения.

## Проверка и ограничения

Автотесты проходят путь подписанный UAM → email OTP → очередь → RCI login →
RADIUS Access-Accept → связанный Accounting-Start. Проверяются перезапуск,
повторы, смена Session-ID, отзыв до/во время команды, истечение разрешения,
неверный сертификат, неподходящий мост/VLAN, границы NAS/ключа тенанта,
скрытие секретов и права API. OIDC сохраняет тот же Session-ID; общая очередь
SMS/email/OIDC проверяется в модуле гостевого доступа. Форма проверена в браузере.

23.11.2026 встроенный адаптер проверен в основном Linux-бинарнике `radiusd`
на физическом Ultra NC-1812 с NDMS 5.1.8 и Mac через отдельный гостевой SSID.
Подписанный UAM → email OTP через SMTP с TLS → RCI → RADIUS → Accounting
открыл HTTPS без переподключения Wi-Fi. Неверный код отклонён. Исходный
Session-ID совпал в UAM, Access-Request и Accounting; Class связал сессию
с разрешением. Домашнее управление из гостевой сети недоступно.

90-секундное разрешение закрыло доступ по сроку. В отдельном прогоне после
перезапуска Border статус остался `active`, HTTPS работал. Досрочный отзыв
записал Disconnect-ACK и Accounting-Stop; HTTPS перестал работать за 6,4 секунды
при оставшейся 51 секунде разрешения. HTTP снова отправил клиента на портал.
Почта доставлялась штатным SMTP-клиентом Border в изолированный TLS-приёмник;
внешние почтовые сервисы этим не проверялись. Тестовый SSID и Chilli отключены,
временный WireGuard, маршруты, DNS и серверные правила удалены.

Публичный TLS и автоматическое окно captive portal, реальная доставка SMS/SMTP,
внешние IdP и другие модели Keenetic требуют отдельных испытаний. Для
WPA-Enterprise результаты captive Accounting/Disconnect неприменимы.
