# Проверка устойчивости сессий, 30 октября 2026

Стенд: Border, Samba AD, RouterOS CHR 7.23.8 в UTM, Ubuntu strongSwan-клиент.
Дополнительный NAS: strongSwan в изолированной Docker-сети. Это проверки
конкретных реализаций, а не сертификация всех моделей Cisco/Huawei/FortiGate/Eltex.

## Потеря Start и повторы

Лабораторный транспорт отбросил три передачи Start одной VPN-сессии, без
поддельного Accounting-Response. VPN передавал трафик. Первый Interim восстановил
строку сессии и счётчики, но без связи с разрешением: RouterOS IPsec не вернул
Class. Такая сессия не участвует в автоматическом отзыве по политике или
блокировке пользователя. Ограничение сохранено намеренно: привязывать только
по логину небезопасно при параллельных VPN и быстрых переподключениях.

Затем Start, Interim и Stop передавались по три раза. Ответы на копии были
одинаковыми, поколение сохранялось, накопленные счётчики не суммировались
повторно (три ping — 252 байта в каждом направлении). Инъекция отключена,
исходный транспорт восстановлен.

В автоматическом тесте стандартного пути с Class потерянный Start восстанавливается
из Interim вместе с разрешением. Повтор после закрытия и повторного открытия
SQLite не меняет поколение и время последнего принятого события. Связь для
отзыва сохраняется. Этот механизм не зависит от словаря NAS.

## Перезапуск Border и LDAP

После перезапуска Border уже установленный VPN остался активным, сохранились
поколение и разрешение; последующие Interim продолжили учёт. Незавершённый
EAP-обмен при перезапуске теряет состояние: клиент должен начать авторизацию
заново. Повторное новое подключение проверено успешно.

На 100 секунд блокировался только LDAPS от процесса Border к лабораторному
каталогу; Samba NTLM-helper оставался доступным. Подтверждены срабатывания
правила блокировки, EAP-Failure нового доменного входа, сохранение старого VPN
с рабочим трафиком и отсутствие ложной блокировки пользователя при фоновой
проверке. После автоматического удаления правила новая авторизация успешна.
Все временные правила удалены.

## Перезапуски NAS и strongSwan

При штатной перезагрузке RouterOS активные VPN получили Stop, после загрузки
Border принял Accounting-On. Новое подключение получило новый Acct-Session-Id,
разрешение и рабочий туннель. Это не тест аварийного отключения питания: при
потере последнего Stop и On достоверное завершение неизвестно до следующего
события или контроля отсутствия обновлений.

На отдельном NAS strongSwan проверены доменная EAP-MSCHAPv2-авторизация,
Class в accounting, передача трафика и адресный Disconnect-ACK с удалением
IKE/CHILD SA на клиенте. При штатном перезапуске контейнера сервера старая
сессия завершилась по Stop; после запуска новое подключение связано с новым
разрешением, трафик проходит. Accounting-On/Off от этого NAS в данном тесте
не наблюдались — не следует считать их поддержку проверенной.

Проверки не требуют RouterOS SSH-адаптера на strongSwan: используется стандартный
RADIUS Disconnect. Аппаратные Cisco, Huawei, FortiGate, Eltex и Keenetic в стенде
отсутствуют; наличие словарей и общая диагностика не заменяют проверки на них.

После первой перезагрузки CHR сохранённый пароль служебного SSH-адаптера
не принимался. Он восстановлен из приватной конфигурации стенда; повторная
перезагрузка подтвердила вход тем же служебным аккаунтом. Причина первоначального
расхождения не установлена; это не изменение алгоритма RADIUS.

## Новая диагностика

Для всех профилей NAS добавлены `AuthorizationLinked`, `AccessPolicyID`, фильтр
`authorization=linked|unlinked`, колонка в панели и счётчик
`border_unlinked_sessions`. Счётчик охватывает активные и потерянные сессии,
не включает завершённые. Токен разрешения не отдаётся API. Непустой токен,
не найденный у того же NAS, не считается связью. Проверены изоляция по NAS,
фильтрация, пагинация, защита API, восстановление из Interim с Class после
повторного открытия базы, Go-тесты, race-тесты store/web и `go vet`.
