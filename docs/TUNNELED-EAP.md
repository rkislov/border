# PEAP и TTLS для 802.1X

Реализованы PEAPv0 с внутренним MS-CHAPv2 и EAP-TTLSv0 с PAP, TLS 1.2.
Метод выбирается явно в политике авторизации (`EAPMethod=peap|ttls`), источник —
local или directory. Политика доступа должна иметь назначение «Сеть», сегмент
и VLAN по расположению/NAS. Для набора политик используется протокол `eap`.
Допустимы основная проверка и проверка устройства; TOTP в этих методах пока
не поддерживается. Пустой EAPMethod сохраняет прежнее поведение.

Включите EAP в настройках тенанта, подготовьте CA и сертификат сервера.
Клиент обязан проверять доверенный CA и DNS-имя сервера. Внешний логин может
быть anonymous: разрешение, группы, VLAN и Class относятся к внутренней личности.
PEAP требует включённого MS-CHAPv2 у локального пользователя; для домена —
Samba/winbind helper и LDAP. TTLS проверяет пароль через обычный local/LDAP backend.
При выбранном туннельном методе обычный PAP не используется как запасной вход.

Пример настроек wpa_supplicant/eapol_test:

```
network={
 key_mgmt=IEEE8021X
 eap=PEAP
 identity="alice"
 anonymous_identity="anonymous"
 password="replace-me"
 ca_cert="/etc/border/ca.pem"
 domain_suffix_match="radius.example.org"
 phase1="tls_disable_tlsv1_3=1"
 phase2="auth=MSCHAPV2"
}
```

Для TTLS замените `eap=TTLS`, `phase2="auth=PAP"`.
Для Wi-Fi задайте SSID и `key_mgmt=WPA-EAP`; для проводного подключения
используйте wired-драйвер supplicant. Пример не содержит реальных секретов.

Ограничения: TLS resumption, PEAP cryptobinding, PEAPv1, TTLS внутренний EAP/CHAP
и TLS 1.3 пока не реализованы. Клиенты, требующие cryptobinding, не совместимы
с этой версией. Не отключайте проверку сертификата ради подключения.

Проверено независимым eapol_test 2.10 в Ubuntu ARM64: оба метода, фрагментация
128 байт, MPPE-ключи, неверный пароль, неверное имя TLS-сервера, блокировка
локального пользователя и истечение политики. Регрессия EAP-TLS также проходит.
Это проверка обмена RADIUS/EAP; физические точки доступа, коммутаторы и штатные
клиенты Windows ещё не проверены.

30 октября 2026 года выполнен отдельный прогон на Linux amd64 с реальным Samba AD:
PEAP-MSCHAPv2 через NTLM-посредник и TTLS-PAP через LDAPS. Для каждого метода
проверены успешный вход и MPPE-ключи, неверный пароль, неверное имя TLS-сервера,
блокировка учётной записи в Samba, разблокировка, временный отказ LDAP,
восстановление LDAP и истечение политики. При отказах новые access_grants
не создаются; успешные разрешения относятся к внутреннему доменному логину,
а не к anonymous. Дополнительно проверен отзыв учтённых сессий через UDP-эмулятор NAS:
по два Acct-Session-Id на выданное разрешение, Disconnect-Request/ACK,
сохранение сессии другого пользователя, отсутствие повторного отзыва старых
сессий и восстановления старых разрешений после разблокировки. Недоступность
LDAP сохраняет как ранее разрешённое, так и ранее заблокированное состояние;
новый вход при этом отклоняется. Истечение политики отзывает оставшиеся
сессии. Синхронизация статуса и обработчик отзыва вызываются явно, без ожидания
периодических таймеров. Accounting-записи создаются через хранилище.
Это не проверка фактического отключения порта на физическом NAS.

В лаборатории BaseDN задан как `CN=Users,DC=lab,DC=border,DC=test`.
Поиск от корня этого Samba AD возвращает referrals: Border отклоняет такой
неполный результат проверки статуса/групп. Для реального каталога задавайте
соответствующую область пользователей; не отключайте эту проверку ради входа.
NTLM-посредник лаборатории допускает только UID службы Border.

### Повторение доменного прогона

`TestDomainTunneledEAPOL` запускается только при наличии
`BORDER_EAP_DOMAIN_CONFIG`. Это путь к приватному JSON (права 0600) с полями:
`Domain` (конфигурация identitysource.Domain, включая CA и bind-пароль),
`Username`, `Password`, `Hook` (абсолютный путь к внешнему сценарию стенда).
Секреты и этот файл нельзя добавлять в git. Вывод eapol_test не попадает
в сообщения об ошибках теста: он может содержать секреты.

Hook вызывается с одним аргументом: `reset`, `blocked` или `ldap-down`.
Он должен использовать выделенную тестовую учётную запись, блокировать LDAP
только для тестового процесса и восстанавливать исходное состояние при reset.
До запуска обязателен независимый от теста таймер отката на случай аварийного
завершения. Тест также вызывает reset при завершении. В выполненном прогоне
LDAP блокировался через OUTPUT REJECT для UID теста и порта LDAPS; счётчик
пакетов подтвердил отказ для каждого метода. После теста правило удалено,
учётная запись включена. Рабочая база Border не использовалась.

```sh
BORDER_EAP_DOMAIN_CONFIG=/private/domain-eap.json \
BORDER_NTLM_AUTH=/absolute/path/to/ntlm-helper \
BORDER_EAPOL_TEST=/usr/bin/eapol_test \
go test ./internal/aaa -run '^TestDomainTunneledEAPOL$' -v -count=1 -timeout=3m
```

Для удалённого стенда можно собрать тестовый бинарник через `go test -c`
с подходящими GOOS/GOARCH и запустить его с теми же переменными окружения.
Локальный регрессионный набор запускается как `TestTunneledEAPOL`.

Спецификации: [RFC 5281](https://www.rfc-editor.org/rfc/rfc5281.html),
[MS-PEAP](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-peap/4043a26f-1cf1-4ba9-9282-d509decbd0a0).
