# Поиск сессий и событий

Версия 0.5.8 добавляет поиск по всей сохранённой истории текущего тенанта, без прежнего ограничения интерфейса последними 200 записями. На странице можно показывать 25, 50, 100 или 200 записей, переходить назад/вперёд и видеть общее число результатов. Фильтры применяются кнопкой «Найти», сброс возвращает первую страницу. Общее обновление сохраняет применённые фильтры и страницу.

Сессии: подстрока в NAS, ID сессии, MAC или имени пользователя; точный статус; период последнего изменения записи. События: подстрока в источнике, идентификаторе, результате или причине; точный результат; период события. Даты интерфейса вводятся в местном часовом поясе браузера, обе границы включены. В SQLite поиск без учёта регистра гарантирован для ASCII; регистр не-ASCII символов зависит от СУБД. `%`, `_` и `!` ищутся буквально, не как шаблоны SQL.

Управление сессиями использует активные/потерянные записи текущей страницы. В запрос действия по-прежнему передаются поколение и данные выбранной сессии: нельзя применить действие к заменившей её сессии по устаревшему выбору.

Защищённые административным входом GET API:

- `/api/sessions?q=alice&status=active&page=1&limit=50`
- `/api/events?q=alice&result=accept&from=1700000000&until=1800000000&page=1&limit=50`

Для тенанта добавляется `/t/<id>`. Ответ содержит `Items`, `Total`, `Page`, `Limit`. Значения по умолчанию: page=1, limit=50; пределы page=1…1000000, limit=1…200, q до 200 байт, result до 80 байт. Время — Unix seconds. Некорректные значения возвращают 400, ошибка/таймаут запроса — 503. Запрос ограничен 5 секундами. Если страница уже отсутствует, возвращается последняя существующая, при пустом результате — первая.

Сортировка: сессии по updated_at DESC, NAS и ID; события по occurred_at DESC и ID DESC. Порядок записей с одинаковым временем детерминирован. Это живые списки, а не снимок истории: поступление, обновление или очистка записей между запросами может смещать страницы и изменять количество. Подстрочный поиск и подсчёт на большой истории могут требовать полного просмотра данных; это не полнотекстовый поисковый индекс.

Миграция 18 добавляет индексы сортировки и результата событий. Старый `/api/state` сохраняет ограниченные списки для совместимости и обзора; новые страницы используют отдельные API. Пагинация не возвращает очищенную историю и не добавляет историю прежних поколений сессии.
