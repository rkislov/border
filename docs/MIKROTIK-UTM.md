# MikroTik CHR: результат проверки 29 октября 2026

Border `0.5.9-dev-mschap` развёрнут на сервере с резервной копией
`/root/border-backup-20261028-144157`. MikroTik CHR 7.23.8 подтвердил
локальный и доменный SSH-вход флагом `R — RADIUS`.

- Тенант `chr-lab`, NAS `127.0.0.2` через SSH/UDP relay.
- `local/chr-test`: локальная политика `lab-ssh`.
- `domain-test`: доменная политика `lab-domain-ssh`, Samba `LAB.BORDER.TEST`.
- Обе привязки используют `mschapv2`, группа RouterOS `read`.
- Проверены отказ при неверном доменном пароле, отказ после отключения
  пользователя в Samba и успешный вход после его включения.
- Accounting Start/Stop поступает в Border; поиск, пагинация, health/metrics
  прошли smoke-проверку после обновления.
- MS-CHAPv2 не обходит TOTP: такая цепочка получает отказ. VPN/MPPE и PEAP
  этим изменением не реализованы. FreeRADIUS не установлен.

Домен создан в Docker (`border-samba-lab`); LDAPS опубликован только на
`127.0.0.1:1636`. Base DN для стенда —
`CN=Users,DC=lab,DC=border,DC=test`, CA проверяется, имя сертификата —
`dc.lab.border.test`. Включён NetBIOS-домен `BORDERLAB`.
Border вызывает `/usr/local/bin/border-ntlm-helper`, который обращается к
ограниченному Unix-сокету `border-ntlm.service`. Border не включён в группу
Docker. Challenge-response передаётся через stdin, секретные ключи не логируются.
Доменные NT-хеши в Border не копируются. Для локальной совместимости отдельный
NT-хеш хранится зашифрованным; включение требует повторного ввода пароля.

Для доменного MS-CHAPv2 логин отправляется без префикса ID-домена:
домен выбирается политикой NAS. LDAP-группы и состояние пользователя читаются
через TLS; ошибки запрещают новый вход. Учётные данные хранятся вне Git в
ограниченных файлах стенда. Лабораторные политики ограничены сроком действия.

# MikroTik CHR в UTM: проверка RADIUS

Проверка 28 октября 2026: RouterOS CHR 7.23.8 (ARM64), Border
0.5.8-alpha.1. ВМ загружена, последовательная консоль и SSH работают.
RADIUS Accounting-On принят сервером. SSH через RADIUS пока **не работает**:
RouterOS отправляет MS-CHAPv2, который Border не поддерживает.

## Конфигурация ВМ

- UTM/QEMU, ARM64, машина `virt-10.0`, 1 ГБ памяти, диск VirtIO.
- UEFI включён, «Использовать гипервизор» выключено: используется TCG.
- Последовательное устройство: встроенный терминал, автоматическое устройство.
- Терминал открывается через меню «Окно → Border MikroTik CHR Lab (Терминал 1)».
- Сеть Host Only: Mac `192.168.128.1/24`, CHR `192.168.128.10/24`.
- Имя RouterOS `Border-CHR-Lab`; DHCP-клиент отключён после назначения адреса.

При HVF этот образ доходил до ядра, затем перезагружался с
`No working init found`. В режиме TCG тот же диск загрузился успешно.
[Разбор совместимости ARM32 userspace с Apple Silicon](https://github.com/tikoci/mikropkl/issues/11).

## Соединение с Border

Трафик UDP 1812/1813 от CHR поступает на Mac, затем передаётся внутри SSH
на сервер Border. Серверная часть отправляет исходные RADIUS-пакеты с
loopback-адреса `127.0.0.2`. Подписи и содержимое пакетов не изменяются.
Публичные порты RADIUS для стенда дополнительно не открывались.

Создан отдельный тенант `chr-lab`:

- Расположение `utm-mac`.
- NAS `127.0.0.2`, словарь `mikrotik`, режим `ssh`.
- Локальная учётная запись `chr-test`.
- Политика аутентификации `lab-local`: локальный пароль.
- Политика доступа `lab-ssh`: группа RouterOS `read`, сессия до 3600 секунд,
  idle timeout 300 секунд, срок действия семь суток от создания стенда.

На CHR настроены `service=login`, RADIUS timeout 5 секунд,
`require-message-auth=yes-for-request-resp`, `use-radius=yes`, accounting
и interim update раз в минуту. Локальная учётная запись admin сохранена.

Локальные скрипты и секреты находятся вне Git в
`~/.local/share/border-lab/` (каталог 0700, файлы секретов 0600).
Для запуска туннеля после перезапуска Mac:

```sh
~/.local/share/border-lab/start-relay.sh
tail -f ~/.local/share/border-lab/relay.log
```

Сначала должна работать ВМ и существующий SOCKS-прокси Mac на
`127.0.0.1:10808`, используемый SSH-подключением через FESS.
Туннель не установлен как автозапускаемая служба. Его журнал содержит
только коды пакетов, номера атрибутов и результат проверки подписи,
без паролей и содержимого challenge/response.

## Результаты

- SSH под локальным администратором CHR: успешно.
- Accounting-On: запрос 4, ответ 5; событие `nas-on` в тенанте Border.
- Access-Request от CHR достигает Border; Message-Authenticator корректен.
- Для SSH отсутствует PAP User-Password. RouterOS использует Microsoft VSA
  для MS-CHAPv2; Border прекращает обработку с `MSCHAP is not supported`.
- Поэтому проверка успешного RADIUS-входа, неверного пароля и блокировки
  пользователя пока не завершена. Тайм-аут не является доказательством
  проверки пароля или применения политики блокировки.

[Документация MikroTik: RADIUS authentication and accounting](https://manual.mikrotik.com/docs/authentication-authorization-accounting/user/)
подтверждает MS-CHAPv2 для парольного входа в RouterOS.

Следующий шаг — отдельная реализация и проверка MS-CHAPv2. Существующий
bcrypt-хеш локального пароля нельзя использовать как NT-хеш: потребуется
явно спроектировать хранение проверочных данных и миграцию пользователей.
Совместимость с AD/FreeIPA и цепочкой TOTP должна проверяться отдельно.

## Отзыв открытой SSH-сессии: 29 октября 2026

Для испытания настроен обратный SSH/UDP-канал от `127.0.0.2:3799`
на CHR и `/radius incoming accept=yes port=3799`.

- При отключении `domain-test` в Samba Border обнаружил блокировку при
  очередной синхронизации (интервал проверки учётной записи около минуты).
- Отправлен Disconnect-Request; получен аутентичный Disconnect-NAK с
  Error-Cause 406 (Unsupported Extension). SSH продолжал выполнять команды.
- Минимальные подписанные запросы с Acct-Session-Id, с/без User-Name,
  с/без Message-Authenticator также получили 406. Это диагностические
  пробы, требование Message-Authenticator в рабочем коде не ослаблялось.
- При истечении короткой политики Border записал `policy expired` и получил
  такой же NAK. SSH-сессия продолжала работу и после Session-Timeout,
  переданного в Access-Accept. Проверка относится к CHR 7.23.8 и SSH;
  поведение PPP/HotSpot здесь не проверялось.
- Border не помечает такую сессию отключённой, сохраняет код ошибки и
  повторяет отзыв. Интерфейс объясняет 406 и предупреждает, что доступ
  может сохраняться.

Тестовые SSH-процессы завершены со стороны клиента, доменный пользователь
включён, исходный срок политики восстановлен. Это ручная уборка стенда,
а не успешный автоматический отзыв.

Для гарантированного отключения SSH на этом устройстве нужен отдельный
адаптер RouterOS управления активными сессиями с ограниченной служебной
учётной записью. На текущей версии заявлять гарантированный отзыв SSH
через RADIUS нельзя.
