# Развёртывание через FESS

На origin устанавливается один Linux-бинарник radiusd. Пример systemd: deploy/border.service; первоначальная инициализация: deploy/bootstrap.py (root, SQLite, имя хоста сертификата адаптировать).

Конфигурация и ключ: /etc/border/border.env, root:root 0600. База: /var/lib/border/border.db, системный пользователь border. Веб-панель слушает loopback 18443, пользовательский портал — loopback 19443. RADIUS UDP 1812/1813 доступен только зарегистрированным NAS с Message-Authenticator; сетевой firewall рекомендуется ограничить адресами NAS.

FESS завершает публичный TLS и проксирует административный сайт через SSH-туннель к origin. Туннель использует отдельный ключ с permitopen только для двух loopback-портов и закреплённый SSH host key. Если FESS не доверяет внутреннему HTTPS-сертификату, tls_skip_verify допустим только внутри этого аутентифицированного туннеля; не используйте такой backend через открытую сеть.

В работающей установке border.kislovs.ru опубликована административная панель. Пользовательский портал не опубликован отдельно. Для его публикации нужен отдельный hostname/FESS backend на порт 19443, действующий TLS и --portal-url. LDAP, SMTP и SMS настраиваются отдельно. По умолчанию гостевой доступ отключён.

Перед обновлением:
1. Остановить border.service.
2. Сохранить бинарник и согласованную копию каталога /var/lib/border, а также /etc/border (ключи CA и master key).
3. Установить новый бинарник и запустить init-db с существующим окружением.
4. Запустить службу, проверить HTTPS, вход и API.
5. При неудаче остановить службу и восстановить одновременно бинарник и базу из одной резервной копии.

Не публикуйте резервные копии, окружение, исходное ТЗ или данные входа. Потеря master key делает зашифрованные секреты недоступными.

Для регулярных зашифрованных копий и проверки восстановления установите
`border-backup.timer`: [инструкция](BACKUP.md). Расписание и история доступны
только корневому администратору в разделе «Резервные копии».
