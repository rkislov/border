# Черновики и пакетная публикация

В панели: **Конфигурация → Политики и доступ → Черновики и публикации**.
Черновики поддерживаются для авторизации, доступа, правил, локальных групп,
логических сетевых сегментов, сопоставлений VLAN с локацией/NAS, одиночной
политики NAS и его набора политик. При обновлении сервера рабочая конфигурация
сохраняется; миграция не публикует черновики автоматически.

## Работа с пакетом

1. Сохраните изменения в соответствующих редакторах. Новые политики и сегменты
   появляются в списках выбора с пометкой «черновик»: на них можно ссылаться
   до публикации. Одиночная политика NAS теперь редактируется отдельной формой.
2. Выберите связанные черновики (до 100) и нажмите «Оценить выбранный пакет».
   Можно оценить один черновик отдельно.
3. Оценка применяет выбранные изменения в транзакции без фиксации, проверяет
   зависимости итоговой конфигурации, совместимость правил и протоколов NAS,
   наличие VLAN для затронутых сетевых привязок. Показывает изменения полей,
   затронутые NAS, связанные активные/потерянные сессии и несвязанные сессии.
4. Для удаления используйте форму «Удаление через черновик» в этом же разделе.
   Выберите тип и объект, создайте черновик и добавьте его в пакет.
5. «Опубликовать пакет» повторяет проверки и одной транзакцией меняет все
   объекты, записывает историю с общим BatchID, ставит разрешения на отзыв
   и удаляет черновики. Любая ошибка отменяет весь пакет.

Сервер сам упорядочивает изменения: сегменты, группы, авторизация, доступ,
правила, сопоставления VLAN, одиночные привязки и наборы NAS. Порядок выбора
в интерфейсе не влияет на результат. После создания/изменения объектов
удаления выполняются в обратном порядке зависимостей. Сохранение черновика проверяет структуру,
но допускает ещё не опубликованные зависимости; полная проверка выполняется
при оценке/публикации. Зависимые черновики не включаются в пакет автоматически:
добавьте их в выбор либо сначала опубликуйте зависимости.

## Влияние на сессии

- Авторизация затрагивает разрешения ссылающихся политик доступа.
- Группа — разрешения политик, в правилах которых используется эта группа.
- Сегмент — разрешения политик, использующих сегмент.
- Сопоставление VLAN — разрешения нужного сегмента на соответствующем NAS
  или в локации. Собственный VLAN NAS имеет приоритет: изменение локации
  не затрагивает NAS с собственным сопоставлением этого сегмента.
- Изменение одиночной политики или набора NAS консервативно отзывает выданные
  разрешения этого NAS, включая ранее выданные по старой привязке.

Повторная публикация неизменившегося обычного объекта не отзывает разрешения.
Публикация наборов правил/NAS повышает их рабочую версию и требует повторного
входа. Сессии других политик/локаций сохраняются, если пакет их не затрагивает.
Отзыв выполняется существующим фоновым обработчиком по разрешению и поколению
сессии, а не только по имени пользователя. Фактическое отключение требует
поддержки Disconnect и доступности NAS. Результаты и повторные попытки видны
в разделе сессий. Публикация сама по себе не означает подтверждённый Disconnect.

Оценка — снимок зависимостей, а не симуляция LDAP или испытание оборудования.
В перечень NAS могут входить выключенные привязки. Несвязанные с разрешением
сессии показаны отдельно и не отключаются этим механизмом. Состав сессий
может измениться между оценкой и публикацией.

## Конфликты и откат

Для вида/ID хранится один общий черновик своей базы/тенанта. Его редакция
монотонна даже после удаления и повторного создания. При публикации сервер
проверяет редакцию каждого выбранного черновика и соответствие рабочей
версии его базе. Конфликт одного объекта блокирует весь пакет. После конфликта
рабочей версии удалите устаревший черновик и подготовьте изменения заново.

История показывает последние 100 изменений, сгруппированных по пакетам;
полная история остаётся в базе. «Подготовить откат» атомарно создаёт черновики
состояния **до выбранного пакета**, сохраняя актуальные номера рабочих версий
наборов правил/NAS. Существующий черновик не перезаписывается. Выберите все
созданные черновики отката, оцените и опубликуйте их. Откат не восстанавливает
отозванные сессии: нужен новый вход.

Полный откат поддерживает все три случая: созданный объект удаляется,
изменённый возвращается к прежнему состоянию, удалённый восстанавливается.
Это относится и к пакетам, опубликованным предыдущей версией Border.
Создание черновиков отката не меняет рабочую конфигурацию; их публикация
снова проходит проверку зависимостей. Внешние ссылки, появившиеся позднее,
могут заблокировать откат — добавьте их изменение/удаление в тот же пакет.

Удаление не обходит зависимости: включая выключенные правила и привязки NAS.
Набор правил доступа нужно удалять отдельным выбранным черновиком вместе
с политикой; скрытого каскадного удаления этих правил нет. Участники группы
и список личностей политики сохраняются в истории родительского объекта
и восстанавливаются вместе с ним. Физические записи сессий, разрешений и
история публикаций при удалении конфигурации не стираются.

Удаление набора правил возвращает проверку списка личностей политики;
удаление набора NAS возвращает одиночную либо прежнюю конфигурацию NAS.
Оцените этот результат перед публикацией. Удаление сопоставления VLAN NAS
может вернуть VLAN локации. Если подходящего VLAN не остаётся, проверка
пакета блокирует публикацию активной сетевой привязки.

Версии наборов правил/NAS продолжают возрастать после удаления и повторного
создания. Старое разрешение не получает действующую версию заново; откат
не очищает причину отзыва и не восстанавливает старую сессию.

Карточки NAS (секрет, словарь, расположение, accounting), локации, каталог
физических VLAN, LDAP и пользователи пока остаются вне пакетной публикации.

## API

Все операции доступны только администраторам своей базы. Для тенанта
используется префикс `/t/<id>`. Все POST, включая оценку, требуют CSRF.

- `GET /api/policy-drafts` — `Drafts`, `Releases` (включая `BatchID`).
- `POST /api/policy-drafts` — `Kind`, `PolicyID`, `Revision` (0 при создании),
  `Payload`. Для удаления — `Operation: "delete"` без Payload (также
  принимается явный `Payload: null`). Ответ содержит `Operation` (`upsert`/`delete`).
  Отсутствие поля Payload само по себе не считается удалением. Виды: `authentication`, `access`, `rules`, `group`, `segment`,
  `mapping`, `nas-assignment`, `nas-policies`.
- `POST /api/policy-drafts/batch/impact` и `/batch/publish` —
  `{"Drafts":[{"Kind":"access","PolicyID":"staff","Revision":1},...]}`.
  Оценка возвращает `Drafts`, `Devices`, `Sessions`, `UnlinkedSessions`, `Errors`.
- `POST /api/policy-drafts/batch/rollback` — `{"BatchID":"..."}`.
- Совместимые одиночные `/publish`, `/discard`, `/rollback` сохраняются;
  одиночная публикация использует тот же пакетный механизм.

У `mapping` ID имеет вид `location/<location>/<segment>` либо
`nas/<canonical-IP>/<segment>`; Payload — `LocationID` или `NAS`, `SegmentID`,
`VLAN`. У обоих видов NAS ID — канонический IP. `nas-assignment` содержит
`NAS` и `AccessPolicyID` (пустая строка снимает одиночную политику).

Старые POST редакторов политик, групп, сегментов, сопоставлений и наборов NAS
теперь создают черновик. Для редактирования существующего черновика используйте
версионированный API. POST `/api/nas` сохраняет текущую одиночную политику;
изменение привязки переносится в `/api/nas-assignment` либо общий API черновиков.

Проверки охватывают удаление и восстановление связанных объектов, откат
первого создания, сохранение версий после пересоздания, совместимость старой
истории, новые взаимозависимые объекты, отказ позднего изменения
без частичной публикации, конфликты редакций, избирательный отзыв VLAN с учётом
переопределения NAS, группы, изоляцию тенантов, откат, CSRF и RBAC.
